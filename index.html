      🔎 Powered by MCP Sentinel

      Guardian reuses real detection data ported from MCP Sentinel, a 183-rule MCP-security registry — 20 rules re-implemented for the browser across three surfaces: DECLARED metadata (A1/A2/A6/A7/A8/A9/B2/B6/B7/G2/G5/I1/I2/J3/J6), the whole tool set (F1 lethal trifecta, I16 consent fatigue), and WITNESSED behavior (E5 declared-vs-observed, J5 tool-output poisoning, G6 mid-session). Sentinel's engine is server-side (Node + Postgres) and can't run in a browser, so Guardian ports the tables and Sentinel's matching strategy — several catalogues verbatim, the UTS-39 confusables and capability graph as curated subsets — and cites the exact rule behind every finding.

      ✓ validated against Sentinel's own red-team fixtures npm run validate → 61/61 (incl. hard negatives + FP regression guards)

      Guardian uses Sentinel's severity vocabulary but produces no risk score — the verdict comes from witnessed behavior, not a points total. Subsets are labeled as such: a look-alike, a capability, or an encoding outside the ported set is a Guardian miss that Sentinel's full server-side rule would still catch.

      Open source (MIT). Guardian judges tools by witnessed behavior (Sentinel E5 declared-vs-observed) — a tool it hasn't run is “not yet observed”, never “safe”.
